# Core

本文件规定 STM32F103ZET6 电赛小车的项目边界、资料优先级和文档维护方法。引脚明细只以 `rules.md` 为准。

## 1. 当前项目边界

- MCU：`STM32F103ZET6`。
- 当前底盘：TB6612 双电机驱动、左右正交编码器、循迹、超声波、OLED、雷达/无线扩展、蜂鸣器、按键和 LED。
- 当前目标：先完成可重复的硬件单元测试，再完成双轮速度控制、循迹/传感器、雷达/无线通信和比赛状态机。
- 旧 MSPM0、旧 `lidarMSP`、旧树莓派雷达文档不再定义当前硬件；仅可借鉴算法、日志格式或问题定位经验。

## 2. 资料优先级

发生冲突时按以下优先级判断：

1. 已确认的实际焊线、实测波形和本轮用户确认的引脚表。
2. `references/rules.md` 的“当前主用引脚分配”。
3. 当前 STM32F103ZET6 工程的 CubeMX/Keil 配置、代码宏定义和原理图。
4. STM32F103xE 官方数据手册、参考手册和封装引脚图。
5. 历史文档、旧项目代码、聊天记录与网络示例。

发生冲突时先记录“谁占用该脚、需要哪个复用、是否已实测”，然后再修改代码；不能通过猜测同时打开两个冲突外设。

## 3. 文档同步规则

每次发生以下任一事件，必须同步更新 `rules.md`：

- 变更 UART、TIM、PWM、ADC、GPIO、DMA 或重映射。
- 发现接线和原设计不一致。
- 确认电机/编码器的左右对应、正反方向或最小可动占空比。
- 一个备用脚变为当前主用脚，或当前主用脚被释放。

随后同步工程配置、代码宏、接线表和 `workflow.md` 的测试顺序。备用脚必须写明启用条件，不能写成“空闲”。

## 4. 当前硬件风险与冲突边界

| 风险点 | 当前处理原则 |
| --- | --- |
| USART1 默认/重映射 | `PA9/PA10` 为 USB 串口主用；`PB6/PB7` 仅在 USART1 重映射后作为循迹串口，二者不并用。 |
| USART2 与电机 PWM | `PA2/PA3` 固定为 `TIM2_CH3/CH4` 电机 PWM；陀螺仪需用 USART2 重映射 `PD5/PD6`。 |
| USART3 与 OLED | `PB10/PB11` 由 OLED/I2C2 优先占用；MaixCam 或临时日志使用 USART3 重映射 `PD8/PD9`。 |
| TIM3 | `PA6/PA7` 固定为右编码器；`PB0/PB1` 只能作为 ADC/普通 IO 备用，不纳入当前电机/编码器链路。 |
| TIM8 扩展 | `PC6/PC7` 是带定时器通道的舵机/步进优先脚；启用前必须检查云台、扩展电机和通用 IO 是否冲突。 |
| 扩展 TB6612 | 本轮临时实物测试使用 `PF1..PF4` 的 TIM7 软件 PWM、`PA4/PA5`、`PD8/PD9` 与 `PB9(STBY)`；必须先禁用数字循迹 `x1..x4`，并暂停 PA4/PA5 模拟预留、PD8/PD9 USART3 重映射、PB9 TIM4_CH4 备用用途。停止时 `PF1..PF4=0`、方向=0、`PB9=0`。 |
| 双 A4988 步进 | 当前使用 A4988-1 `STEP/DIR/EN=PE14/PE13/PC4`、A4988-2 `STEP/DIR/EN=PD14/PD13/PD15`；无编码器仅可开环计步，整圈/回零必须用人工标记或外部限位/传感器验证。 |
| PG1 | 默认属于灰度循迹 GPIO 组；只有该功能未启用时才可作为普通 IO 候选。 |
| 电机安全 | 电机供电、逻辑地、TB6612 `STBY`、方向脚和 PWM 必须逐项验证；不带日志/观测依据不进入 PID。 |

## 5. 开发优先级

1. USB 串口日志、按键/LED、TB6612 单轮方向与 `STBY`。
2. TIM2 PWM、左右编码器、最小可动占空比与方向符号。
3. 超声波、蜂鸣器、循迹 ADC/GPIO、OLED。
4. 雷达 UART4、无线/ESP32 UART5、陀螺仪 USART2 重映射、MaixCam USART3 重映射。
5. 速度环、动作测试、循迹与比赛状态机。

## 6. 软件边界

```text
driver (GPIO/TIM/UART/ADC)
  -> service (motor/encoder/sensor/protocol/logger)
  -> app or stage runner (test flow/state machine)
```

- `motor_driver` 只负责 PWM、方向、刹车和 `STBY`。
- `encoder` 只负责 TIM5/TIM3 的计数、方向和速度反馈。
- `protocol` 只负责 UART 帧收发与校验。
- `speed_loop` 只消费目标轮速和编码器反馈，输出 PWM。
- `heading_pid` 只消费陀螺仪 yaw 误差并输出左右目标轮速差；它不得直接写 PWM、方向脚或 `STBY`，必须经两个 `speed_loop` 内环。
- 测试动作由 `motion_test` 或阶段调度发起，不能把测试逻辑塞进中断。

## 7. 高价值防错规则

1. 先做单轮方向和编码器，再做双轮，再做闭环。
2. 一次只改变一个变量：接线、复用、方向符号、PWM 频率或控制参数不能同时改。
3. 对照引脚表时，区分“外设默认脚”“重映射脚”“当前主用脚”和“候选脚”。
4. 新硬件没有日志或可观测信号时，先补串口/OLED/LED/示波器观测，不盲目调参。
