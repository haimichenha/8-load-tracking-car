# STM32F103ZET6 电赛小车 Rules

## 1. 使用范围与维护规则

本文件是当前小车唯一有效的 pin-map 基线，适用于 STM32F103ZET6。每项引脚均分为：

- **当前主用**：当前工程应直接配置和测试的功能。
- **备用/重映射**：必须关闭冲突功能、配置 AFIO 重映射并写入变更记录后才能使用。
- **条件候选**：只在明确未使用其优先功能时可使用。

用户在 2026-07-26 确认的引脚表优先于旧 MSPM0/lidarMSP 文档。任何代码、原理图或历史笔记与本表不一致时，先以实际焊线复核，再同步本表。

### 临时扩展 TB6612 开环测试覆盖（2026-07-28）

操作者已明确本轮**只为测试额外 G513**，暂时释放数字循迹 `x1..x4=PF1..PF4`。此覆盖仅对 `ExpansionActuatorTestDebug` 有效；该固件不得初始化或读取 `x1..x4`，测试完成后必须使 `PF1..PF4=低` 并恢复循迹输入配置。

| 扩展 TB6612 功能 | 本轮临时引脚 / 模式 | 释放或冲突条件 |
| --- | --- | --- |
| AIN1 / AIN2 | `PA4 / PA5` GPIO 输出 | 暂停这两脚的模拟/DAC 预留用途。 |
| BIN1 / BIN2 | `PD8 / PD9` GPIO 输出 | 暂停 USART3 重映射 MaixCam/临时日志。 |
| STBY（高有效） | `PB9` GPIO 输出 | 暂停 TIM4_CH4 备用用途；不影响 `PB8/TIM4_CH3` 蜂鸣器。 |
| G513-A 的 ENA / ENB | `PF1 / PF2`，TIM7 软件 PWM、同占空比 | `x1/x2` 循迹输入已临时释放。 |
| G513-B 的 ENA / ENB | `PF3 / PF4`，TIM7 软件 PWM、同占空比 | `x3/x4` 循迹输入已临时释放。 |

旧的 `PC8/PC9 + PG2..PG6` 只是未实测的历史候选，不得和本轮临时接线混用。上电、停止、错误或串口超时必须令 `PF1..PF4=0`、方向脚=0、`PB9(STBY)=0`。本轮只允许 `G` 原始开环方向序列，未分配额外编码器，禁止接入 `SpeedLadrc`。

## 2. 当前主用引脚分配

### 2.1 UART / 串口复用

| 串口 | 当前主用 / 优先功能 | 引脚与方向 | 备用或重映射功能 | 冲突与启用条件 |
| --- | --- | --- | --- | --- |
| USART1（T1） | USB 串口日志/调试 | `PA9=TX`，`PA10=RX` | `PB6=TX`，`PB7=RX`：USART1 重映射后用于循迹串口 | 默认 USB 串口与 PB6/PB7 重映射循迹串口不能同时启用。 |
| USART2（T2） | 默认脚不作串口，固定给电机 PWM | `PA2=TIM2_CH3` 左 PWM，`PA3=TIM2_CH4` 右 PWM | `PD5=TX`，`PD6=RX`：USART2 重映射后给陀螺仪 | 禁止把 USART2 默认功能配置到 PA2/PA3；启用陀螺仪时必须使用 PD5/PD6 重映射。 |
| USART3（T3） | `PB10/PB11` 优先保留给 OLED（I2C2 SCL/SDA） | `PB10`、`PB11` | `PD8=TX`，`PD9=RX`：USART3 重映射给 MaixCam 或临时日志导出 | OLED 使用 PB10/PB11 时，USART3 必须走 PD8/PD9；临时日志结束后释放。 |
| UART4（T4） | 雷达串口 | `PC10=TX`，`PC11=RX` | 无 | 当前默认雷达 UART，不与其他外设复用。 |
| UART5（T5） | ESP32 通信或无线模块扩展；偶尔日志导出 | `PC12=TX`，`PD2=RX` | 无 | 作为通信扩展口，临时日志导出不得占用比赛通信时段。 |

**串口连线方向规则**：MCU `TX` 接外设 `RX`，MCU `RX` 接外设 `TX`，所有串口设备必须共地。未明确协议/波特率时，不把旧项目的协议参数当成当前结论。

### 2.2 TB6612 电机驱动与编码器

| 子系统 | 功能 | 引脚 | 外设 / 模式 | 状态 |
| --- | --- | --- | --- | --- |
| 左电机 | PWM | `PA2` | `TIM2_CH3` | 当前主用 |
| 右电机 | PWM | `PA3` | `TIM2_CH4` | 当前主用 |
| TB6612 | `IN1` | `PE2` | GPIO 输出 | 当前主用 |
| TB6612 | `IN2` | `PE3` | GPIO 输出 | 当前主用 |
| TB6612 | `IN3` | `PE4` | GPIO 输出 | 当前主用 |
| TB6612 | `IN4` | `PE5` | GPIO 输出 | 当前主用 |
| TB6612 | `STBY` | `PE6` | GPIO 输出 | 当前主用；拉高才允许驱动 |
| 左轮编码器 | A / B | `PA0` / `PA1` | `TIM5_CH1` / `TIM5_CH2` 编码器模式 | 当前主用，TIM5 专用 |
| 右轮编码器 | A / B | `PA6` / `PA7` | `TIM3_CH1` / `TIM3_CH2` 编码器模式 | 当前主用，TIM3 的 CH1/CH2 专用 |

电机方向对照在第一次单轮实测后固定到代码配置中：正向命令、轮子实际方向、编码器计数正方向必须在同一张测试记录中确认。未经实测，不在文档中假定哪个 `INx` 对应“前进”。

#### 已实测方向标定记录（2026-07-26）

测试固件为 `Src/main.c` 的 G513/TB6612 原始方向测试，PWM 为 35%，每个动作约 1.5 s，车轮架空观察。车头方向以“前”为准：

| 侧别 | 首个原始阶段 | 首个实际方向 | 第二个原始阶段 | 第二个实际方向 | 后续车体“前进”符号 |
| --- | --- | --- | --- | --- | --- |
| 左电机 | `LEFT_RAW_POS`：`PE2=0, PE3=1` | 后 | `LEFT_RAW_NEG`：`PE2=1, PE3=0` | 前 | `MOTOR_LEFT_FORWARD_SIGN = -1` |
| 右电机 | `RIGHT_RAW_POS`：`PE4=1, PE5=0` | 后 | `RIGHT_RAW_NEG`：`PE4=0, PE5=1` | 前 | `MOTOR_RIGHT_FORWARD_SIGN = -1` |

`bsp_motor.h` 已按本结论配置左右 `MOTOR_*_FORWARD_SIGN=-1`；因此 `Motor_SetSpeed(..., 正值)` 统一表示车体前进。

#### 编码器 B3 实测记录（2026-07-28）

测试固件：`EncoderBringupDebug`；采样周期 20 ms；USART1 `PA9/PA10` 经 J-Link CDC UART 以 115200 8N1 采集；原始电机测试占空比为 35%。`raw_delta` 为未进行软件方向修正的 TIM 编码器计数。

| 测试阶段 | 车体实际方向 | 原始命令 | 左 raw_delta | 右 raw_delta | 稳态中位数（计数/20 ms） | 结论 |
| --- | --- | --- | ---: | ---: | --- | --- |
| `LEFT_FORWARD` | 前 | 左 `-35` | `-3814` | `0` | 左 `-54` | 左轮前进时 TIM5 原始计数为负，设 `ENCODER_L_INVERT=1`。 |
| `LEFT_REVERSE` | 后 | 左 `+35` | `+3672` | `0` | 左 `+52` | 与左轮前进符号结论一致。 |
| `RIGHT_FORWARD` | 前 | 右 `-35` | `0` | `+4044` | 右 `+57` | 右轮前进时 TIM3 原始计数为正，设 `ENCODER_R_INVERT=0`。 |
| `RIGHT_REVERSE` | 后 | 右 `+35` | `0` | `-4062` | 右 `-57` | 与右轮前进符号结论一致。 |

因此，**经方向修正后的 `Encoder_GetCount()` 正值统一表示车体前进**。停止阶段仍有约 800 脉冲的同向余量，这是 `Motor_StopAll()` 关闭 `STBY` 后的滑行，不作为编码器噪声或刹车效果判断。每轮真实计数/圈与实际轮径尚待“手动整圈计数”测试确认；在此之前，速度内环可使用“修正后计数/20 ms”作为反馈单位，不得向外环宣称 mm/s 精度。

#### A4988 PE7..PE12 改线尝试回退记录（2026-07-28）

曾按用户口述 `DIR / STEP / EN` 尝试 A4988-1=`PE10 / PE11 / PE12`、A4988-2=`PE7 / PE8 / PE9`。**A4988 只有 `DIR / STEP / EN`，没有 `STBY`；`EN` 为低有效。**该组 GPIO 本身可用、当前扩展测试未启用 FSMC，且串口台账能完成保持力/单步/16 步命令；但用户确认实际硬件存在问题，因此此映射不作为当前可用方案。

源代码已恢复到 Git 暂存基线：A4988-1=`DIR/STEP/EN=PE13/PE14/PC4`，A4988-2=`DIR/STEP/EN=PD13/PD14/PD15`。在操作者把实体导线也恢复到该基线前，**不得将已恢复的 A4988 固件烧录后用于动作测试**。工程虽编译了历史 `bsp_l298n.c` / `bsp_mecanum.c`，其中会使用部分 `PE7..PE12`，但 `ExpansionActuatorTestDebug` 的 `main_expansion_actuator_test.c` 不调用这些历史初始化函数，故该专用测试固件运行时无冲突；后续若切回并调用历史 L298N/麦轮初始化，必须先停止并重新分配这些 PE 脚。

**A4988 关键边界：**两块驱动器的 `VDD` 使用 3.3 V 逻辑电平、`VMOT` 使用符合电机额定值的独立电机电源，MCU/A4988/电机电源必须共地；每块 A4988 的 `VMOT-GND` 近端须有合适的电解电容；先按电机额定电流设置电流限流。首次测试将 `MS1/MS2/MS3` 硬件设为全步进（均为低）并保证 `RESET/SLEEP` 为高；若改为细分，必须同步修改 `microstep_divider`，不能继续把 200 个脉冲当作一整圈。

首次发 STEP 前，可用 `ExpansionActuatorTestDebug` 的 `E` 命令仅使能两块 A4988 线圈 5 s；此时不发脉冲，轴应出现可感觉的保持阻力，结束后 `EN` 自动回到高电平。若没有保持力，先核对 `VDD`、`VMOT`、所有 GND 共地、`RESET/SLEEP=高`、`EN` 与线圈 A/B 对，而不是继续增加 STEP 脉冲或盲调速度。

#### A4988 改线初测记录（2026-07-28，双机同步已确认）

用户将 A4988-1 改为 `DIR=PE13`、`STEP=PE14`、`EN=PC4`，A4988-2 改为 `DIR=PD13`、`STEP=PD14`、`EN=PD15`。上述六脚与当前主用外设无复用冲突；`PC4/PD13/PD14/PD15` 不再可作为自由排针 IO。改线后的 `+16/-16`（电机1）与 `+16`（电机2）均观察到轻微短暂动作，证明两路在新 pin-map 下至少有可见响应；16 个全步仅约 28.8°，不应期待整圈。

单机 `A`（电机1）和 `B`（电机2）已各执行一次低速正向 200 脉冲，串口台账均为 `issued=200/200`，用户确认两台都能持续转动。`C` 已于 2026-07-28 执行，日志 `logs/expansion_actuator_both_pos200_20260728-1632.log` 中两路均从 `issued=0` 到 `200/200`，完成后 `EN` 自动释放；用户确认两台可同时持续动作。**双机同步动作通过，但 200 脉冲的实际转角不够精确，不能再将其标为“已确认一整圈”。**

下一步先在两根轴端贴零位标记，以 `D` 同时反向发送等量 200 脉冲，检查是否回到起点；随后核对电机步距角和 `MS1/MS2/MS3` 真实电平，再把 `microstep_divider` 和每圈脉冲数改为实测值。已确认当前接线下的 `C`（两机正向、`DIR=1`、各 200 脉冲）物理方向：面对电机、以红色电线一侧作为观察基准时，两台均为**逆时针**。反向 `D` 的实际方向、零位标记等量回零、保持力与长期不丢步仍待确认。仅当 `MS1/MS2/MS3` 均为低、且电机为 1.8°/200 步型号时，200 脉冲才是一次整圈尝试；禁止直接使用自动 `P` 序列。

**无编码器的反馈定义：**A4988 没有位置或丢步反馈。软件只能记录“已发出脉冲数（commanded steps）”，不能称为真实位置闭环。验证一圈/回零时，应在轴端做可见零位标记，发送 `full_steps_per_rev × microstep_divider` 个脉冲正转一圈，再发同数脉冲反转并人工检查标记是否回零；要获得自动回零或可靠丢步检测，后续必须增加限位开关、霍尔/磁编码器或外部位置传感器。

#### 速度内环初测记录（2026-07-28）

测试固件：`SpeedLadrc600Debug`；车轮架空；控制周期 20 ms；串口日志周期 100 ms；一次运行阶段为 8 s。速度环实际使用左右**修正后编码器计数/s**闭环，`600 mm/s -> 3520 counts/s` 仅由暂定 `880 counts/rev` 与 `150 mm/rev` 换算得到。

| 指标 | 左轮 | 右轮 | 结论 |
| --- | ---: | ---: | --- |
| 目标速度 | 3520 counts/s | 3520 counts/s | 两轮目标一致。 |
| 稳态末 3 s 平均 | 3545.2 counts/s | 3535.5 counts/s | 相对目标误差分别约 `+0.71%`、`+0.44%`。 |
| 稳态末 3 s 绝对误差平均 | 38.1 counts/s | 36.1 counts/s | 已达到可进入直行/外环前准备的速度稳定度。 |
| 90% 上升时间 | 500 ms | 500 ms | 由 100 ms 串口采样记录估计。 |
| 稳态 PWM 平均 / 范围 | 43.1% / 40~46% | 42.3% / 39~46% | 未触及本轮 55% PWM 安全上限，也未触发堵转保护。 |

本轮采用 `b0=800`、`wc=8`、`wo=40` 的初始 LADRC 参数。原始 20 ms 差分速度存在 50 counts/s 的量化台阶，稳态 PWM 在约 39~46% 间调整；后续滤波复测只改变速度反馈与控制带宽，**不改变**已确认的电机/编码器引脚与方向。

#### 速度内环单变量滤波复测记录（2026-07-28）

测试固件：`SpeedLadrc600FilteredDebug`；车轮架空、20 ms 控制、100 ms 串口记录、8 s 运行。相对 `SpeedLadrc600Debug` 初测，**只改变**速度反馈：采用最近 4 个编码器差分的滚动平均（约 80 ms）；`b0=800`、`wc=8`、`wo=40`、目标 3520 counts/s、PWM 上限 55% 均保持不变。串口同时记录原始与滤波后 counts/s。

| 指标 | 左轮 | 右轮 | 结论 |
| --- | ---: | ---: | --- |
| 目标速度 | 3520 counts/s | 3520 counts/s | 与初测相同。 |
| 稳态末 3 s 平均 | 3520.4 counts/s | 3519.8 counts/s | 平均误差分别 `-0.4`、`+0.2 counts/s`。 |
| 稳态末 3 s 绝对误差平均 | 9.4 counts/s | 10.1 counts/s | 相比初测的 38.1 / 36.1 counts/s 明显减小。 |
| 90% 上升时间 | 500 ms | 500 ms | 与初测一致。 |
| 稳态 PWM 平均 / 范围 | 42.1% / 41~43% | 42.1% / 41~43% | 相比初测 40~46% / 39~46% 更平稳。 |
| 原始-滤波速度差绝对值平均 | 23.0 counts/s | 21.9 counts/s | 验证四点窗口主要抑制 20 ms 差分量化台阶。 |

结论：`SpeedLadrc600FilteredDebug` 作为当前**架空速度内环调试基线**保留；两轮均未达到 55% PWM 上限且未触发堵转保护。此前以 `wc=7`、`wo=30` 同时改动滤波和带宽的探索性日志保留在 `logs/speed_ladrc_600_filtered_COM13.log`，不用于单变量调参结论。规范的复测日志为 `logs/speed_ladrc_600_window4_baselinegains_COM13.log`；分析脚本为 `scripts/analyze_speed_ladrc_log.py`，可同时解析初测的旧日志格式与滤波版格式。该结论仍仅验证 counts/s 内环；在完成手动整圈计数和实际轮径测量前，禁止将“600 mm/s”作为真实地面线速度标定值。

#### 陀螺仪直线串级控制测试准备（待实测，2026-07-28）

测试固件：`GyroStraight400Debug`。它不替代已验证的速度内环，而是在其上增加一个**航向外环 PID**：WIT/JY 角度帧（`USART2` 重映射 `PD5/PD6`）→ 100 ms 航向 PID → 左右目标速度差（counts/s）→ 两个 20 ms `SpeedLadrc` 速度内环 → `TIM2 PA2/PA3` TB6612 PWM。默认目标为暂定 `400 mm/s`（仅作 counts/s 换算），速度反馈使用四点窗口，PWM 上限 45%。

接线与协议假设：陀螺仪 `TX -> PD6(RX)`、可选 `PD5(TX) -> 陀螺仪 RX`、GND 共地；当前解析器接受 WIT/JY 正常输出的 `0x55 0x53` 角度帧，预设 `9600 8N1`。模块型号、供电/逻辑电平和输出频率尚未实测，因此这些均为**待确认**，不得当作已完成的通信结论。

安全测试顺序固定为：`O` 同速观察 → `N` 650 ms 小差速标定 → `C` 闭环直行。`N` 的正向差速定义为左目标速度较低、右目标速度较高；仅当其 yaw 变化绝对值至少 `0.8°` 时，程序才保存 `yaw_response_sign` 并允许 `C`。USART2 RX 使用中断环形缓冲，避免 115200 诊断日志阻塞主循环时丢失 9600 波特率 WIT 帧；`rx_overflows` 必须保持为 0。任一阶段陀螺仪角度帧超过 350 ms 未更新、或达到原有编码器堵转条件时，立即 `Motor_StopAll()` 关闭 `PE6(STBY)`。`C` 只允许正向、限时 6 s、差速修正限幅 ±240 counts/s；未经地面实测，不修改 PID 参数或宣称直线精度。

## 3. 复用冲突一览

| 引脚/资源 | 优先用途 | 不可同时启用的用途 |
| --- | --- | --- |
| `PA0/PA1` + TIM5 | 左编码器 | USART1 重映射不占用，但任何普通 GPIO/其他定时器配置都不能覆盖 TIM5 编码器。 |
| `PA2/PA3` + TIM2 | TB6612 PWM | USART2 默认 TX/RX。 |
| `PA6/PA7` + TIM3 | 右编码器 | 其他 TIM3 CH1/CH2 输出或普通 GPIO。 |
| `PB6/PB7` | USART1 重映射循迹串口 | USART1 默认 PA9/PA10 同时工作模式。 |
| `PB10/PB11` | OLED / I2C2 | USART3 默认 TX/RX。 |
| `PD5/PD6` | USART2 重映射陀螺仪 | 需确认没有其他外设占用，再启用 AFIO remap。 |
| `PD8/PD9` | USART3 重映射 MaixCam/日志 | 需关闭 PB10/PB11 上的 USART3 默认功能；OLED 仍占 PB10/PB11。 |
| `PB0/PB1` | ADC/普通 IO 备用 | TIM3_CH3/CH4 输出。 |
| `PC6..PC9` | TIM8 舵机/步进云台 | 与任何其他高优先扩展功能同时分配。 |
| `PC8/PC9` + TIM8 | 扩展 TB6612 的双路 PWM（待实测） | TIM8_CH3/CH4 云台 PWM。 |
| `PE13/PE14/PC4` | A4988-1 的 `DIR/STEP/EN` | 引出排针或未登记 GPIO。 |
| `PD13/PD14/PD15` | A4988-2 的 `DIR/STEP/EN` | 引出排针或未登记 GPIO。 |
| `PG2..PG6` | 扩展 TB6612 方向与 `STBY`（待实测） | 任何未登记的 GPIO/复用功能。 |
| `PG1` | 灰度循迹 GPIO | 未释放前不能再列为通用 IO。 |

## 4. 硬件测试顺序与观测点

1. **B0：供电/SWD/USB 串口**：确认主控 3.3 V、共地、烧录、`PA9/PA10` 日志。
2. **B1：按键/LED**：逐个验证 `PG9..PG13`、`PG14/PG15/PE1` 的电平极性。
3. **B2：TB6612 单轮**：先 `PE6(STBY)`，再方向 `PE2..PE5`，最后 `PA2/PA3` 低占空 PWM。
4. **B3：编码器**：分别手转/低速转动左右轮，验证 TIM5 `PA0/PA1` 与 TIM3 `PA6/PA7` 的计数和正负号。
5. **B3.5：扩展执行器**：本轮临时映射下，先测扩展 TB6612 的 `PF1..PF4 + PA4/PA5 + PD8/PD9 + PB9` 原始正反转；仅当 `x1..x4` 已释放时可运行。再按零位标记验证两块 A4988 的单步、16 步、整圈正反转和双机同步。A4988 无编码器时只记录指令步数，不进入闭环。
6. **B4：基础传感器**：超声波 `PF0/PA8`、蜂鸣器 `PB8`、OLED `PB10/PB11`。
7. **B5：循迹**：ADC 主组 PC0..PC2，再测 PF1..PF9 数字组；备用脚只在需要时单独启用。
8. **B6：通信**：按优先级接 USB、雷达 UART4、无线/ESP32 UART5；陀螺仪和 MaixCam 必须使用对应重映射脚。
9. **B7：闭环/比赛功能**：仅在 B0~B6 的日志完整、引脚冲突为零时进入。

## 5. 模块接口规则

| 模块 | 允许负责 | 禁止负责 |
| --- | --- | --- |
| `bsp_motor` / `motor_driver` | TIM2 PWM、PE2..PE6、停止和安全使能 | 读取雷达、解析串口、决定比赛状态 |
| `encoder` | TIM5/TIM3 计数、速度与方向 | 直接写电机 PWM |
| `line_sensor` | ADC/GPIO 采样、归一化和线偏差 | 直接进行 PID 或驱动电机 |
| `ultrasonic` / `buzzer` / `oled` | 各自外设状态 | 改变核心控制状态 |
| `uart_*` / `protocol` | UART 帧收发、校验、缓存 | 直接控制电机 |
| `speed_loop` | 左右目标速度与编码器反馈到 PWM | 访问 UART、雷达、按键业务逻辑 |
| `stage_runner` | 调度安全测试、收集日志 | 代替 BSP 配置寄存器 |

## 6. 变更记录格式

每次变更必须至少记录：

```text
日期 | 外设/引脚 | 原状态 | 新状态 | 复用配置 | 实测方式 | 结果 | 回退方式
```

没有实测结论的引脚只能标“待确认”，不能标“已确认”。
