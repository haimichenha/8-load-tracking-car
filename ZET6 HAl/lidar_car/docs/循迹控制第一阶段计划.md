# 循迹控制第一阶段：控制意图干运行（已归档）

> 当前首跑实现已切换为 `LineFollowMissionDebug`；本页下半部分保留干运行边界，
> 不能再被当作当前电机控制行为。

## 已完成输入证据

- 白底基准：`all_white_mask=0x00`；
- 居中：`X4|X5=0x18`，`err_x100=0`；
- 黑线在车体左：`X4=0x08`，`err_x100=-100`；
- 黑线在车体右：`X5=0x10`，`err_x100=+100`；
- A 点全黑：`0xFF`，只能是路径位置标记，不能启动任务。

证据索引：`logs/gray_tracking_sync_20260730.md`。

## 当前 A 点至 D 点联合观测首跑（2026-07-30，已构建、待落地验证）

`LineFollowMissionDebug` 使用 `LineObserver_t` 联合保存灰度、gyro yaw 与 yaw-rate：

```text
gray mux -> nonlinear gray differential / yaw-rate reference
         -> gyro heading + rate bounded differential correction
         -> left/right target counts/s -> dual front SpeedLadrc
         -> four-wheel signed actuation
```

- 基础速度：**600 mm/s = 3520 counts/s（暂定轮径/每圈计数换算）**。2026-07-28 架空
  600 mm/s 日志约为 598/600 mm/s、PWM 42/42%，但这不是落地循迹通过证据。
- 速度保护：中弯 500、急弯 420、离开 A 400、宽线 380、丢线保持 360 mm/s；前轮
  TB6612/前轮编码器闭环，后轮以同侧 PWM **开环跟随**。后轮编码器 TIM4/TIM8 尚未标定，
  因此不得称为四轮速度闭环。
- 物理前进符号以四驱架空合格镜像为唯一来源：前左/前右/后左/后右为
  `-1/-1/+1/-1`。已收敛到 `bsp_four_wheel_direction.h`，循迹镜像和四驱镜像共同引用；
  这修复了首版循迹镜像仅前轮动作且正逻辑物理倒车的回归。
- 安全启动：仅 **KEY2=PG10（低有效）**；必须位于 A 点全黑 `0xFF` 且 gyro angle 帧新鲜。
  跑动中再次按 PG10 或串口 `S` 都会关闭前、后 TB6612 的 STBY。
- A 点逻辑：400 mm/s 离开 A，连续 3 个正常线样本后进入 TRACK；一圈后 A 点持续 200 ms
  自动停车。首次尝试到 D 点时，由操作者按 PG10 停车。
- 故障逻辑：丢线仅按最后差速保持 400 ms；gyro 超过 250 ms 不新鲜、编码器不动、或运行
  超过 45 s 都安全停车并冻结日志。
- 无线联调：MCU 已接入 UART4 的 Pi 位姿入口。首选 V2.2
  （`src=0x31,dst=0x32,type=0x80,len=22`）；同时兼容已实装的本地 14 B `FA...AB` 雷达帧，
  但后者只能标记为未校准预检显示数据。收到位置/yaw 有效、CRC 正确（V2.2）且不超过 250 ms
  的样本时，MCU 改写为 `src=0x30,dst=0x10`，每 `100 ms` 广播一次 `CAR_POSE`；运行位由 MCU
  按实际电机状态设置。Pi 位姿不新鲜时，
  跑动小车保持无线静默；静止维护态才每 `500 ms` 发送固定 8 B 的 `HEARTBEAT(0x03)`。
  该心跳载荷为 `device_status(u8)`、`error_code(u8)`、`reserved(u16=0)`、
  `uptime_ms(u32, big-endian)`，不能启动飞行器。
  在 TaskType、MissionId、CalibrationId 与重试策略就绪前，**不发送**正式
  `0x81 CAR_TASK_REQUEST`。

冻结日志流程：停车后连接 J-Link CDC，执行

```powershell
.\scripts\capture_line_follow_frozen_log.ps1 -PortName COM13
.\scripts\analyze_line_follow_frozen_log.ps1 -Path <上一步输出的日志路径>
```

首轮只判断三件事：灰度差速符号是否令车向正确一侧转、双轮速度能否跟随目标、gyro 的 yaw/
yaw-rate 是否全程新鲜。先不增加速度，也不把雷达位置闭环接入。

## 已归档的干运行边界

`app_line_follow_control.*` 是纯计算模块。`GrayTrackingDebug` 每个采样周期输出：

```text
ctrl_state,target_vx,steer_demand,steer_dir,motor_permit
```

- `TRACK`：候选 `target_vx=400`（沿用已有速度命令的 `V_x` 标度），按
  `steer_demand = clamp(2 * err_x100, -250, +250)` 计算转向意图；
- `LOST_HOLD`：白底/丢线，速度与转向意图均为零；
- `A_MARK_HOLD`：全黑 A 点，速度与转向意图均为零；
- `WIDE_HOLD`：多于 3 个头同时有效，速度与转向意图均为零；
- `motor_permit` 固定为 `0`。本阶段没有包含 `Motor_Init()`、`Motor_Enable()`、
  `Motion_Car_Control()` 或任何 PWM 写入。

负 `steer_demand` 的语义是“应朝车体左侧转向”，正值是“应朝车体右侧转向”。它尚未
绑定到 `Motion_Car_Control(V_x, V_y, V_z)` 的 `V_z` 符号；该符号必须通过单独的低速
转向与编码器回归确定。

3. 仅在第 2 步通过后，把控制意图映射到已验证的编码器速度内环；初始速度使用候选
   `V_x=400`，并设置最大转向、丢线保持和人工急停。

   丢线和停车距离。`600` 只能在 `400` 实测通过后复验。
