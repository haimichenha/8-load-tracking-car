## 当前结论

`LineFollowMissionDebug` 已具备可继续联调的车端基础：PG13/PG9 任务选择和二次
急停、PG12 维护键、灰度/JY901/编码器循迹、12 s 失线搜索、20 s 卡滞保护、90 s
整圈计时、任务二 B 点 15 s 记录、`0x81/0x82/0x02/0x84` 框架均在小车工程内。

但截至本清单版本，**不能宣称满足 V2.3 的正式空地计分闭环**。原因不是编译或
小车循迹，而是坐标和校准所有权仍与权威协议不一致，且飞机、机载 ESP32、Pi 位姿桥、
地面站和实飞证据不在本仓库。

## 强制门槛

| 编号 | 权威要求 | 当前车端状态 | 计分影响 | 关闭条件 |
| --- | --- | --- | --- | --- |
| G1 | DOCX 3.1 要求 `CAR_POSE` 表示平台同心圆十字中心；当前单向 Pi 兼容链采用固定坐标约定 `X_lora=-(X_pi-13 cm)+DeltaX`、`Y_lora=-Y_pi+DeltaY`、`yaw_lora=yaw_pi` | 当前 MCU 已按该兼容公式发送，原始/出站的实车同心圆几何尚未留存证据 | 坐标符号、偏移或物理中心任一不一致都会使空侧/地面站位置错误 | 抓取 Pi 原始帧和 LoRa 出站帧逐帧验证该公式，并用场地实测证明其对应平台中心；未证明前不得主张严格通过 |
| G2 | 场地 Delta 由 Pi 应用；MCU 转发 `0x83`，等待 Pi 成功 ACK 后才对地面站 ACK（3.3、5.3、6.1） | 当前 MCU 本地保存 Delta 后直接 ACK 地面站 | 与发布的 V2.3 控制事务不一致 | 接通 `PC10 MCU TX -> Pi RX`，部署 Pi 校准 ACK；或取得赛题方对 MCU 所有权方案的书面确认并使所有端同步协议 |
| G3 | PG12 维护复位先由 Pi 清校准、回 ACK，MCU 再发三帧 `0x85`（附录 C） | 当前 PG12 直接清 MCU 本地状态并广播 | 复位语义与正式链路不一致，Pi 可能保留旧校准 | 同 G2，完成 Pi 清除/ACK 后再广播，并验证旧 ID 无法恢复 |
| G4 | 飞机只接受连续三帧新鲜、校准、平台中心 `CAR_POSE` 后的任务 | 当前原始 Pi V2.3 三帧/未校准约束尚在迁移；旧 `FA...AB` 仍可被用于出站兼容显示 | 旧流不能作为正式协同或得分证据 | 只允许 native V2.3 原始输入建立 `0x81`；Pi 重启后重新获得三帧有效输入和正式校准 |
| G5 | 小车开始运动时发出无线起飞任务，飞控仅在预检通过后 ACK；重发不重复触发 | 本地无雷达模式可先循迹、后补发 `0x81` | 无即时 `0x81`/ACK 的一圈只能证明循迹，不能证明任务一/二 | 正式起跑前完成 G1--G4 并录到同一轮 `motion_start -> 0x81 x3 -> ACK -> 0x82/0x02` |
| G6 | 车端 10 Hz、空端 2 Hz、100 ms 时隙、10 分钟错误统计 | 编码和调度已在 MCU 中；无完整三端 10 分钟实测 | 互操作未验收 | 保存地面站、车端、机端三份时间序列，统计 CRC/长度/乱序/丢帧 |
| G7 | 任务一抛投、任务二动态降落和再起飞、地面站实时图形显示 | 不在本仓库 | 80 分任务与 15 分地面站均不可由本工程单独获得 | 连续视频、飞控状态、地面站截图和验收记录齐全 |

## 可以继续的联调层级

| 层级 | 允许的结论 | 不允许的结论 |
| --- | --- | --- |
| L0 车端本地循迹 | 灰度/JY901/编码器、A 点停车、失线恢复、转弯与看门狗工作 | 任务一或任务二已得分 |
| L1 无线帧台架 | CRC、长度、地址、时隙、`0x81/0x82/0x02/0x84` 收发可观测 | 飞控实际接受任务或完成飞行动作 |
| L2 临时 MCU 本地校准 | MCU 本地 Delta、ACK、出站坐标变换可重复 | 已符合 DOCX 规定的 Pi 校准/复位事务或严格得分 |
| L3 正式计分联调 | 关闭 G1--G7 后，带 Pi/飞控/机载无线/地面站的完整场地运行 | 未留存端到端证据时的口头通过 |

## 本轮最小闭环顺序

1. 先决定正式策略：恢复 Pi 双向校准链路，或取得对 MCU 本地校准架构的明确协议变更。
2. 校验坐标映射：同时抓取 Pi 原始帧和 LoRa 出站帧，逐帧确认
   `X_lora=-(X_pi-13 cm)+DeltaX`、`Y_lora=-Y_pi+DeltaY`、`yaw_lora=yaw_pi`。只检查校准前后
   差值不足以证明镜像已生效。
3. 仅用 native V2.3 Pi 帧执行三帧就绪、`0x83`、三帧校准后 `CAR_POSE`、`0x85` 清除的
   台架闭环；`FA...AB` 仅可留作迁移诊断。
4. 对每个任务录制从 `motion_start` 开始的完整证据：`0x81` 三次、空侧 ACK、阶段、B 点、
   A 点、90 s 与视频。任务二还必须有 15 s B 点和平台停留/再起飞证据。

## 证据命名

每次正式尝试建立同一时间戳目录，至少包含：

```text
acceptance.md
car_serial.log
ground_station.log
air_radio.log
flight.log
video.mp4
```

`acceptance.md` 必须写明镜像 SHA、硬件接线、Pi/飞控/地面站版本、场地、
`CalibrationId`、Delta、G1--G7 状态和最终结果。没有这些字段时，只能记录为
调试尝试，不能升级为计分证据。
