# 2026-07-30 PG9 地面站维护事件与循迹优化准备记录

## 实现范围

- `PG9` 配置为低有效物理键；连续按住 `2 s`，且车端状态已连续静止 `12 s` 后才有效。
- 有效按下不向 UART4 雷达/Pi 写入任何信息；MCU 将在连续三个小车发送时隙直接广播
  `MAINTENANCE_RESET (0x85)` 到 LoRa 广播地址。
- 三帧使用同一非零 `ResetId`、同一 `Seq` 与相同 8 B payload；后两帧仅增加
  `RETRANSMISSION` 标志。按键不会启动、停止或恢复循迹。
- 正常 TRACK/WIDE 弯道保留 `600 mm/s` 基础速度；灰度/航向差速上限提高到 `5000 cps`，
  X4/X5 保持零点并增强单侧中心传感器捕获；外侧误差达到 `400` 时仅外轮额外增加 `10% PWM`。
- 边缘传感器后的全白失线，在 `180 ms` 内延续该边缘方向；否则使用最近三帧差速均值，
  `650 ms` 内未重获仍安全停车。

## 协议边界

`D题_通用通信与接口规范_v2.3.docx` C.3 的正式校准清除流程要求 Pi 清除状态并 ACK。
本次按使用者决定为不向 Pi 发数据的地面站联调配置，故不清除 Pi 中任何可能残留的
`CalibrationId` 或偏置。仅可在 Pi 已未校准时测试地面站接收；若 Pi 开始持久保存校准，
必须恢复完整 Pi 清除/ACK 事务后才可作为正式维护复位。

### 航向中心泄放反例与回退

`line_follow_frozen_20260730_heading_recenter.log` 的终点为 `LINE_LOST_TIMEOUT`，故该版
**不能作为有效优化保留**。虽然边缘占比为 53.6%，但在最后弯道重新达到 `err=700`，出现
`X8 -> all-white`，随后 650 ms 内未恢复。中心泄放仅减少了局部直线航向残余，未降低关键
弯道的最大误差，且没有提高完整圈可靠性，因此已回退该修改。

失败序列还暴露了一个直接控制退化：失线前 X8 为 `-5000 cps / 外轮55%`，进入
`LOST_HOLD` 后却降为 `-3600 cps / 外轮45%`，使寻线动作反而变弱。历史 `33348 B` 镜像曾
烧录并作如下针对性尝试（后续失败，当前不保留）：

- 撤销未验证的航向中心泄放，恢复上一版完整一圈的航向控制；
- `LOST_HOLD` 定向寻线差速由 `3600` 提至 `4400 cps`；
- `LOST_HOLD` 外轮同样允许 `+10%`，上限 `55%`，不再在 X8 后削弱转向。

### 失线增强后的状态抖动

`line_follow_frozen_20260730_lost_recovery_attempt.log` 仍以 `LINE_LOST_TIMEOUT` 停止，
且实车观察到“卡顿”。日志表明电机不是意外断电，而是状态机在边缘抖动：

`X8(err=700) -> all-white(LOST_HOLD) -> X8(TRACK) -> all-white(LOST_HOLD)`。

旧代码一出现单帧 `TRACK` 就退出 `LOST_HOLD`，使目标在 `4200/500` 与 `4200/1020 cps`
之间反复切换，造成机械卡顿，最终仍未把线拉回内侧。历史 `33440 B` 镜像曾尝试：

- 仍保留失线 `4400 cps / 外轮55%` 的定向寻线；
- 只有连续 **3** 个内侧 `X3..X6`（`|err|<=300`）TRACK 样本才退出 `LOST_HOLD`；
- 单帧 X1/X8 重现不再使状态来回切换，避免卡顿。

该状态门限版本未跑完，故作为反例保留，不是当前控制基线。
